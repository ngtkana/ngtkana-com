# 設計思想

## なぜAstroか、なぜUIフレームワークを使わないか

このサイトはほぼ静的な1ページのプロフィールサイトで、クライアント側の状態管理はほぼ必要ない（モバイルメニューの開閉、スクロールに応じたナビのハイライトくらい）。React等のUIフレームワークとその実行時コストを持ち込む理由がないため、Astro（`output: "static"`）を採用し、React/Vue等のアイランドフレームワークは使っていない。

わずかに必要なクライアント側の処理は、各 `.astro` コンポーネント内の素の `<script>` で書く（DOM操作、`IntersectionObserver` など）。フレームワークの状態管理は使わない。

## なぜ素のCSSか（Tailwind等を使わない）

ユーティリティCSSフレームワークではなく、`src/styles/global.css` にCSSカスタムプロパティでデザイントークンを定義し、各コンポーネントはAstroのコンポーネントスコープ `<style>` を使う。トークンの階層は [docs/DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) を参照。

## 静的出力 + sirv

`astro build` で `dist/` に静的ファイルを生成し、Dockerコンテナ内では `sirv` で配信するだけ（Node製のアプリサーバーは動かさない）。SSRが必要になる要素がないため、ビルド時に全ページを生成し切る方針。

## サイドバー + メインカラムのレイアウト

`>=1024px` では左に sticky なサイドバー（名前・タグライン・主要SNS・ページ内ナビ）、右にメインコンテンツを並べる2カラム構成（`src/pages/index.astro` の `.page-shell`）。それ未満の幅ではサイドバーが通常のブロックとして上部に折りたたまれ、代わりにモバイル用のハンバーガーメニュー（`MobileNav.astro`）がページ内ナビを担う。

サイドバーはコンテンツの隣に置かれるため、Hero等のコンテンツの上に重なるナビ要素を持たずに済む。

## コンテンツはコードに直書き

CMSは使わず、プロフィール文・SNSリンク・フレンドコード・活動履歴などは `src/pages/index.astro` 内のTypeScriptの配列に直書きしている。更新頻度が低い個人サイトであり、CMS導入のコストに見合わない。具体的な編集箇所は [docs/CODE_TOUR.md](CODE_TOUR.md) を参照。
